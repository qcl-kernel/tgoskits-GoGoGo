# 协议对比分析：RT-IPC (UDP) vs HRPC (TCP)

> **定位**：本文是任务二传输层选型的依据——基于这组 host 侧（x86_64 本机
> 回环）基准数据，我们决定 RT-IPC v2 采用 **UDP** 而非 TCP：延迟敏感的
> 实时控制通道需要 RT-IPC 的 ~6 µs 级中位 RTT 与可预测时序（避免 TCP 拥塞
> 控制引入的停顿），可靠性（ACK/超时/重传/去重）在应用层自行实现。
> 虚拟化 guest 之间的实际通信指标见[性能数据](性能数据.md)。

## 测试环境

- 主机：x86_64 Linux（本机回环）
- Rust：1.95.0，release profile（opt-level=3，lto=thin）
- 测试：延迟测 1000 次迭代，带宽测 3 秒时长

## 1. 延迟（往返时间 RTT）

RT-IPC（UDP）在延迟上全面优于 HRPC（TCP）：

| 载荷 | RT-IPC 平均 | HRPC 平均 | RT-IPC p99 | HRPC p99 |
|---------|-------------|-----------|-------------|----------|
| 0 B     | 6.1 µs      | 10.9 µs   | 12.4 µs     | 17.5 µs  |
| 64 B    | 7.0 µs      | 11.8 µs   | 9.6 µs      | 21.7 µs  |
| 256 B   | 8.3 µs      | 12.4 µs   | 13.8 µs     | 15.5 µs  |
| 1024 B  | 13.3 µs     | 19.1 µs   | 20.1 µs     | 35.0 µs  |
| 4096 B  | N/A（上限 1400 B） | 35.3 µs | N/A       | 42.8 µs  |
| 8192 B  | N/A         | 60.3 µs   | N/A         | 102.6 µs |

**关键发现**：在所有可比较的载荷大小下，RT-IPC 的中位延迟比 HRPC 低约
40%。这符合预期：UDP 避开了 TCP 的连接状态跟踪、序列校验和 ACK 捎带
开销。

RT-IPC 不能处理超过 1400 字节的载荷（设计如此，避免 IP 分片）。HRPC 通过
TCP 流每帧最多可承载 64 KB。

## 2. 带宽（吞吐量）

| 载荷 | RT-IPC Mbps | HRPC Mbps | RT-IPC 包/秒 | HRPC 包/秒 |
|---------|-------------|-----------|---------------|------------|
| 64 B    | 443         | 465       | 729K          | 631K       |
| 256 B   | 1236        | 1100      | 576K          | 484K       |
| 1024 B  | 2587        | 2439      | 312K          | 290K       |
| 1400 B  | 2972        | 3012      | 263K          | 264K       |
| 4096 B  | N/A         | 4130      | N/A           | 125K       |
| 16384 B | N/A         | 4998      | N/A           | 38K        |
| 65536 B | N/A         | 5230      | N/A           | 10K        |

**关键发现**：在可比较的载荷大小（≤1400 B）下，两者吞吐量几乎相同
（约 3 Gbps）。小载荷时 RT-IPC 的包速率略高，因为每包开销更低（12 B vs
28 B 头部+尾部）。大载荷时 HRPC 领先，得益于 TCP 的批量发送和更少的每
字节系统调用。

## 3. 内存占用

| 组成部分            | RT-IPC/UDP | HRPC/TCP |
|--------------------|------------|----------|
| 每包头开销  | 12 B       | 24 B     |
| 可靠性状态  | 25 KB      | 8.5 KB   |
| 总 RSS        | 2.79 MB    | 2.79 MB  |

RT-IPC 的内存主要用于重排序缓冲（64 项 × ~324 B）和发送窗口（16 个待确认
包）。HRPC 的内存主要由 FrameReader 缓冲（8 KB）构成，整体更轻。

## 4. 重连（仅 HRPC）

HRPC 在服务器被杀后约 100 ms 内成功重连（首次尝试）。重连后的数据流已验
证。RT-IPC 没有连接概念（无状态 UDP），因此重连不适用。

## 选型建议

- **延迟敏感的控制指令**（小载荷，< 1400 B）：RT-IPC/UDP 提供最低延迟，
  中位 RTT 约 6 µs。
- **批量数据传输或载荷 > 1400 B**：HRPC/TCP 是更好的选择，吞吐 5+ Gbps
  且无载荷大小限制。
- **追求简单**：HRPC/TCP 所需的应用层可靠性代码更少（TCP 原生处理
  ACK/重传/重排）。
- **确定性时序**：RT-IPC/UDP 避开了 TCP 拥塞控制带来的停顿，延迟更可预测
  （代价是需要自行实现可靠性）。
