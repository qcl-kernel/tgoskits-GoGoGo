## 0. 五级性能证据体系

本项目的性能结论建立在五个层级上，本章 §1–§4 为 8 组合矩阵批次
（2026-08-27，rebase 后复验），§5 为更早的专项长测批次（说明书正式基线，
QEMU 平台）。矩阵批次验证功能闭环与跨平台一致性；专项长测提供统计意义
上的分布与长尾结论：

| 层级 | 规模 | 用途 | 所在章节 |
|---|---|---|---|
| 实时专项（A/B/C 对比） | 9 指标 × 100,000 样本 | 原生 vs 虚拟化 vs 共存的隔离开销分解 | §5.1 |
| 实时稳定性 | 300 s / 299,999 样本 | 周期抖动持续性与 1 ms 丢样门禁 | §5.2 |
| 网络长测 | 3600 s / 每载荷 240,000 请求 | Linux vs StarryOS 的 RTT 与吞吐 | §5.3 |
| AI 完整测试 | 600 FIXED + 600 AI 帧 | 准确率、闭环时延、MAE 改善 | §5.4 |
| 8 组合矩阵（本批次） | 16 指标 × 10 样本 × 8 组合 | QEMU+真机 × 双 RTOS × 双应用 OS 的功能门禁与跨平台一致性 | §1–§4 |

## 1. Timer jitter（核心实时性指标）

| 平台 | RTOS | 应用客户机 | p50 (ns) | p99 (ns) |
|---|---|---|---:|---:|
| QEMU | RT-Thread | Linux | 4,896 | 244,720 |
| QEMU | RT-Thread | StarryOS | 8,768 | 83,472 |
| QEMU | Zephyr | Linux | 647,584 | 1,295,168 |
| QEMU | Zephyr | StarryOS | 398,352 | 797,104 |
| ROCK 4D | RT-Thread | Linux | 1,000 | **28,125** |
| ROCK 4D | RT-Thread | StarryOS | 459 | **8,875** |
| ROCK 4D | Zephyr | Linux | 1,038,625 | 2,081,625 |
| ROCK 4D | Zephyr | StarryOS | 1,039,583 | 2,083,166 |

要点：

- **真机 RT-Thread 的 p50 达到亚微秒级**（0.5–1 µs），p99 在 9–28 µs——
  hypervisor 隔离开销对轻量 RTOS 是可接受的。
- Zephyr 的 jitter 在两个平台上都是毫秒级（p50 ≈ 1 ms）：其 tickless
  内核以 1 ms 级粒度调度 idle 退出，属于 guest 侧设计权衡而非 hypervisor
  开销；同一平台上 Zephyr 与 RT-Thread 的差异主要来自 guest 内核本身。
- QEMU TCG 的单线程翻译显著放大延迟（RT-Thread p99 245 µs vs 真机 28 µs），
  QEMU 数据只用于功能闭环与同平台相对比较。

## 5. 专项长测批次（说明书正式基线，QEMU）

以下数据来自更早的专项长测（QEMU 11.0.2、AArch64 virt、GICv3、TCG，宿主
x86_64；RT-Thread 为实时客户机）。测试场景定义：

- **A 原生实时客户机**：RT-Thread 直接运行于 QEMU（1 vCPU），无 hypervisor
- **B AxVisor + 实时客户机**：单 RT-Thread guest，vCPU 固定 pCPU 2
- **C 应用/实时共存**：AxVisor + 2vCPU Linux（pCPU 0/1/3）+ RT-Thread
  （pCPU 2）——即本项目的混合关键性形态

### 5.1 实时专项：A/B/C 对比（10 万样本）

P99 / 最大值，单位 µs，数值越低越好；N/A 为原测试场景未提供：

| 指标 | A 原生 | B AxVisor+实时 | C 应用/实时共存 |
|---|---:|---:|---:|
| 定时器抖动 | 12.240 / 242.096 | 26.576 / 585.232 | 441.824 / 905.040 |
| 回调执行 | 0.448 / 36.976 | 0.608 / 149.904 | 1.920 / 173.072 |
| 抢占 | 8.240 / 16.640 | 5.280 / 147.152 | 5.648 / 139.840 |
| IRQ | 6.144 / 49.552 | 83.136 / 276.176 | 84.064 / 294.528 |
| IRQ→任务 | 2.704 / 33.840 | 305.744 / 883.840 | 289.088 / 781.776 |
| 关中断区间 | 0.240 / 20.112 | 0.320 / 234.320 | 0.368 / 212.240 |
| 互斥锁反转 | 11.760 / 51.040 | 18.384 / 394.320 | 22.752 / 1035.504 |
| 负载下唤醒 | 1.392 / 41.152 | 3.088 / 251.536 | 3.232 / 429.984 |
| 网络事件 | 99.200 / 199.776 | N/A | 939.536 / 1786.752 |

**隔离开销分解**：

- B/A 的定时器抖动 P99 比约 **2.17×**——虚拟化本身（world switch、vGIC
  转发、vtimer 发布）的代价。
- C 场景稳定性 P99 = 422.208 µs、300 s 最大周期抖动 827.280 µs——加入
  Linux 共存后的尾延迟放大，但**仍为亚毫秒级**且无丢样。
- 抢占 P99 在 A/B/C 三场景基本持平（8.2/5.3/5.6 µs），说明静态 CPU 分区
  有效保护了实时任务的核心调度路径——共存压力主要落在定时器与网络事件
  的尾延迟上，而非调度本身。

### 5.2 300 秒实时稳定性

三组均 299,999/299,999 样本，missing=0、miss_1ms=0。单位 µs：

| 场景 | P50 | P95 | P99 | P99.9 | 最大值 | 回调最大值 |
|---|---:|---:|---:|---:|---:|---:|
| A 原生 | 0.624 | 3.200 | 10.608 | 37.280 | 176.432 | 36.672 |
| B AxVisor+实时 | 3.472 | 14.464 | 23.056 | 148.912 | 421.280 | 150.464 |
| C 应用/实时共存 | 66.960 | 370.080 | 422.208 | 443.392 | 827.280 | 172.048 |

C/A 的 P99 比约 39.8×、C/B 约 18.3×；但三组最大周期抖动均低于 1 ms 且
300 秒无丢样——共存形态在 QEMU 仿真配置下具备持续运行稳定性，同时量化
了共存对尾延迟的影响量级。

**与真机（8 组合矩阵）的衔接**：ROCK 4D 上 RT-Thread 共存的 timer jitter
P99 为 8.9–28 µs（§1 表），显著优于 QEMU C 场景的 422 µs——QEMU TCG
单线程翻译放大了共存干扰；真机数据更接近虚拟化的真实代价。

### 5.3 Linux 与 StarryOS 3600 秒网络对比

两组对每种载荷均完成 240,000/240,000 请求；应用超时、协议错误、重复、
乱序和传输错误均为 **0**。

RTT（平均 / P95 / P99 / P99.9，ms）：

| 载荷 | Linux | StarryOS |
|---|---|---|
| 64 B | 2 / 3 / 3 / 11 | 6 / 9 / 10 / 46 |
| 256 B | 2 / 3 / 4 / 15 | 6 / 9 / 10 / 46 |
| 1024 B | 2 / 3 / 4 / 14 | 6 / 9 / 10 / 47 |

吞吐（KiB/s 与比值）：

| 载荷 | Linux | StarryOS | StarryOS/Linux |
|---|---:|---:|---:|
| 64 B | 25.16 | 8.82 | 35.1% |
| 256 B | 99.30 | 35.18 | 35.4% |
| 1024 B | 391.92 | 139.31 | 35.5% |

StarryOS 平均 RTT 约为 Linux 的 3 倍、吞吐约 35.5%——差异是性能效率而非
功能存活性（两者长期零错误）。与 §2 矩阵批次数据一致：矩阵批次中 StarryOS
作为应用客户机的 64B RTT（12–15 ms 真机）也约为 Linux（2 ms）的数倍。

### 5.4 1200 帧 AI 控制完整对比

600 FIXED + 600 AI，共 1200/1200 请求成功；错误、超时、重试、重复、重连
均为 0：

| 指标 | 结果 | 判读 |
|---|---|---|
| 分类准确率 | 593/600 = **98.83%** | 满足模型输出有效性要求 |
| 推理 mean/P95/P99/max | 607/903/1042/1520 µs | P99 ≈ 1.04 ms |
| 闭环 RTT mean/P95/P99/max | 6142/30784/30954/31522 µs | 端到端长尾 ≈ 31.5 ms（QEMU） |
| RTOS 处理 mean/P95/P99/max | 95/267/289/320 µs | 实时侧 P99 < 0.3 ms |
| FIXED tracking MAE | 9809 | 固定参数基线 |
| AI tracking MAE | **6065** | **相对基线下降 38.17%** |

**关键结论**：AI 参与后跟踪误差相对固定参数基线下降 38.17%——这是任务三
「AI 控制效果优于固定基线」的直接量化证据（本批次矩阵的 3 帧冒烟样本因
确定性负载设计使二者判位一致，见[任务对照](任务对照.md)的说明；完整
1200 帧统计才呈现 AI 优势）。
