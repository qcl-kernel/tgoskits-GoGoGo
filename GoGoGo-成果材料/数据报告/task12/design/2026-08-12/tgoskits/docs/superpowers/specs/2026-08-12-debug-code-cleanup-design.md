# Axvisor RT-Thread 调试代码清理设计

## 目标

清理 `rtthread-guest` 分支为定位实时性、调度和 virtio-net 中断问题而加入的实验性调试代码，使默认构建只保留产品功能、必要的运行日志和可重复的验证工具。

清理不得改变以下行为：

- RT-Thread 固定物理核心运行；
- Linux 以双 vCPU 运行；
- virtio-net 使用即时中断注入，不退回轮询；
- Linux 与 RT-Thread 通过 RT-IPC/UDP 通信；
- 现有实时性及网络测试仍可用于验收。

## 清理边界

### 删除

1. `virtualization/axvm` 中的 `rt_trace` 运行时跟踪模块、调用点、feature 和依赖接线。
2. 仅用于采集或复现调度跟踪的 board/QEMU 配置。
3. QEMU 调度探针、线程映射、临时 vCPU 亲和性诊断脚本和对应的脚本测试。
4. 为定位 QEMU PPI、MTTCG exclusive 等问题保留的临时诊断补丁。
5. 本分支新增的高频 GIC distributor、IRQ 路由、virtio-net 收发和 UART 调试输出。
6. 仅为输出上述调试信息而存在的配置字段、辅助函数、常量和条件编译分支。

### 保留

1. 编译错误、启动失败、设备初始化失败、中断投递失败和协议错误日志。
2. 低频且能确认系统拓扑或启动状态的结构化日志。
3. AArch64 物理 SPI 路由、GIC 硬件 LR 注入、延迟 deactivate 及 RT-Thread 中断驱动 virtio-net 实现。
4. RT-IPC 协议核心、Linux 客户端、RT-Thread 服务端及其单元、可靠性和端到端测试。
5. 抢占延迟、中断延迟、网络 RTT 等基准程序、数据处理工具和中文测试报告。
6. 用户拥有的未跟踪文件 `run_test.sh` 和 `run_committed_test.sh`。
7. Rust 的 `Debug` trait 派生和上游已有的常规 `debug!`、`trace!` 调用，除非分支差异证明其专为本轮诊断加入且输出频率过高。

## 判定规则

每一处候选代码按以下顺序判断：

1. 是否参与设备初始化、中断路由、虚拟化状态转换或协议处理；参与则保留功能逻辑。
2. 删除后是否影响测试、基准或故障定位所需的错误信息；影响则保留。
3. 是否只采集临时实验数据、打印每次事件或支持已经结束的诊断路径；是则删除。
4. 功能逻辑与调试输出混合时，只删除输出及其纯调试状态，不回退整个提交。

该规则避免按文件名或提交整体回退，从而保护当前尚未提交的中断注入实现。

## 实施方式

采用精确清理，而不是回退调试提交或仅关闭 feature：

- 从 Cargo feature、模块声明和调用点向内删除 `rt_trace`，确保没有悬空 feature 或依赖。
- 删除明确只用于诊断的配置、脚本和补丁，并同步清理文档中的失效入口引用。
- 以 `dev...HEAD` 和工作树差异为依据审查新增日志，删除高频临时输出；不机械删除历史日志。
- 对混合文件做最小行级修改，不覆盖用户已有改动。

## 验证

清理完成后至少执行：

1. 搜索已删除模块、feature、配置和诊断标记，确认无失效引用。
2. `cargo fmt --check` 或仓库等价格式检查。
3. RT-IPC 单元测试与可靠性测试。
4. Axvisor/AxVM 相关 Cargo 构建或检查。
5. 可执行时运行 QEMU 启动/网络冒烟测试；若受镜像或宿主能力限制，明确记录未执行项。
6. `git diff --check`，确认没有空白错误。

验证重点是清理不会把即时中断注入改回轮询，也不会破坏 Linux 双 vCPU、RT-Thread 核心亲和性和 RT-IPC 网络路径。

## 代码量统计

在清理前记录基线，在清理后使用相同口径复算：

- 变更文件数、增加行、删除行和净增加行；
- 清理动作本身删除的文件数及增删行数；
- 当前工作树相对 `dev` 的总体差异；
- 按 Axvisor、virtualization、RT-Thread/guest、RT-IPC、测试与文档分类的差异。

统计以 Git 跟踪文本文件的 `numstat` 为主，排除构建产物、镜像、二进制文件和两个用户未跟踪脚本。结果同时给出“已提交分支”和“包含当前工作树修改”口径，避免未提交中断实现造成歧义。

## 完成条件

- 删除项不存在有效代码引用；
- 保留项未被误删；
- 适用的构建和测试通过；
- 即时中断注入路径仍在；
- 输出一份可复核的清理清单和代码量统计。
